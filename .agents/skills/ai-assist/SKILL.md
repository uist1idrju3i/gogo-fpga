# ai-assist（AI 機能の変更）

## 守る条件

外部への AI 相談の接続先は `openrouter.ai` だけです。別のホストへの転送や、資料の自動送信を加えません。利用者が「送信内容を確認」で本文を確認し、続いて「送信する」を押すまで相談や資料を送りません。エラー説明の操作も入力と資料の選択だけにとどめます。

モデル一覧の `GET https://openrouter.ai/api/v1/models` だけは、利用者が「モデル一覧を取得」を押した場合に限って照会できます。画面の読み込みやモデル入力では取得しません。認証は任意の公開一覧なので鍵を付けず、Cookie、参照元、キャッシュ、転送も使いません。応答の容量と形式を検査し、不正な応答や上限を超える応答を破棄します。一覧はタブ内のメモリーだけに保持し、保存しません。

確認した本文の UTF-8 バイト列と送信するバイト列を一致させます。送信直前に本文を作り直してはいけません。種類、モデル、相談文、資料、ソースなどの変更では、既存の `inputs_changed` で確認を取り消します。古い確認からの送信を許しません。

利用鍵は API の Authorization ヘッダーだけに付けます。本文、URL、ログ、画面、エラー、テストの成果物に含めず、モデルにも要求・開示させません。既定では接続をタブ内だけに保持し、永続保存は利用者が明示して選んだ場合だけです。鍵の保存と削除は `web/lib/openrouter-auth.mjs` の経路を使います。

ユーザーメッセージの JSON にある `files`、`logs`、`problems`、`project` は信頼できない資料です。資料に書かれた指示をシステムの指示として扱いません。要約にファイル本文を混ぜず、本文は選択したファイルだけにします。日本語、根拠の `path:line`、不明点の明示、Verilog-2005 と VHDL の範囲を維持します。SystemVerilog の対応は案内しません。

提案の上限は `web/lib/ai-proposals.mjs` の `PROPOSAL_LIMITS` が正です（最大 8 ファイル、各 128 KiB、合計 512 KiB）。部分編集も組み立てた全文で上限を検査します。正規化したプロジェクト内の相対パスだけを許し、重複、親への移動、ファイルとディレクトリーの衝突を拒否します。`.cst`、ライブラリー、バイナリーの変更を許しません。新しい HDL ファイルは `src/` または `tests/` の下に限ります。ピンはボード画面で設定し、`.cst` は生成します。

`gogo-fpga-changes` は JSON の全文置換です。教師役と採点の講評以外では、相談の種類が変更を許すかどうかは指示にだけ反映し、`parseProposals` の解析と安全検査を実行します。教師役と採点の講評では提案を解析せず、全文置換・部分編集のフェンスが返っても適用カードを作りません。適用は利用者の選択後に限り、一度の適用を一つの改訂として保存します。送信時と内容が違う場合、別プロジェクトや処理中の場合の拒否を維持します。取り消しは元の内容を戻し、新規ファイルを削除します。適用後に編集された内容を取り消しで上書きしません。

既存ファイルの小さな変更は `gogo-fpga-edits` の JSON でも提案できます。`changes` の各項目に `path`、`reason`、`edits: [{search, replace}]` を指定し、新規ファイルや大きな書き直しには `content` で全文を使います。提案用のフェンスは一つだけです。`search` は空にせず、本文からそのままコピーします。送信時に記録したエディターの内容に記載順で置換し、各 `search` が直前までの置換後の本文にちょうど一回一致することを検査します。一致なし・複数一致なら、そのファイルの変更全体を拒否して理由をカードに出します。組み立てた全文を既存の検査・差分・適用・取り消しに渡し、送信後の編集との競合を許しません。

変更の適用後に出す合成・シミュレーション・形式検証のボタンは、既存の手元の検査だけを開始します。実行中のツールを停止せず、処理中は無効にします。取り消し、会話の消去、新しい確認・送信、プロジェクト切り替えで隠します。検査の失敗を説明する操作は対象ログを選ぶだけにし、OpenRouter への送信には改めて確認と明示的な送信を必要とします。

## 端末内の補完

補完は Chrome 内蔵 AI の Prompt API（`globalThis.LanguageModel`）だけを使います。OpenRouter や Ollama への切り替え、通信の API、補完設定の送信は加えません。既定は無効で保存もしません。対応状況の照会だけではモデルを作らず、有効にするクリックの中で `create()` を呼びます。未対応のブラウザー・端末と Android では使えない旨を表示し、取得中は進捗を知らせます。初回のモデル取得は Chrome が行います。

`local-completion.mjs` の上限を正とし、現在のファイルだけを使います。カーソル前は2 KiB、後は1 KiBまでで、UTF-8 の文字を途中で切りません。ファイルを含まない基のセッションを複製し、要求ごとに破棄するため、前のファイルを文脈に持ち越しません。入力後600 msまたは Alt+\\ で求め、一度に一件だけ扱います。編集・カーソル移動・ファイルやプロジェクトの切り替えで中止し、古い候補を表示しません。

候補は制御文字を除き、400文字・8行までに制限し、後続の本文を繰り返すだけなら捨てます。CodeMirror の widget に `textContent` で表示し、Tab は候補がある場合だけ挿入します。候補がなければ従来のキー操作を保ちます。Esc は候補を閉じ、挿入は通常の取り消せる編集にします。模擬 `LanguageModel` と通信先の監視で検査し、実際のモデルや端末で試した結果とは区別します。トップレベルで使うため Permissions-Policy の追加は不要で、CSP と配信ヘッダーは変更しません。

## 採点と講評

`ai-grading.mjs` は通信せずに採点します。ルートの `rubric.json` は `version: 1` と `criteria` だけを持ち、各項目のキーは `id`、`title`、`points`、`check` だけです。項目は1〜20件、idは重複なしで64文字以内、題は200文字以内、合計1000点以内、ファイルは16 KiB以内です。`simulation` と `formal` は整数で1点以上、`comment` は0点とします。不正なファイルは日本語で知らせ、採点も講評の送信も行いません。ファイルがない場合だけ、シミュレーション50点、形式検証50点、設計への講評0点の標準基準を使います。

実行開始時のプロジェクト識別子・編集改訂・検証設定を結果に記録します。ファイル変更や AI の適用・取り消しで改訂が進み、設定変更でも結果が古くなります。古い結果、未実行、実行中、対象なし、停止は「未実行」の0点とし、理由を表示します。成功だけ満点で、それ以外は0点です。結果はタブ内だけに保持し、再読み込みやプロジェクト切り替え後は実行し直します。

8番目の `grade` は「採点の講評」で、`allowsChanges: false` です。確認本文の `grading` に基準、項目ごとの機械判定、点数と合計を入れ、選択した資料と一緒に送ります。モデルの返答は `{"comments":[{"id":"基準のid","comment":"講評"}]}` だけとし、非対応モデルには `gogo-fpga-grade` フェンスを求めます。既知の id、一意性、各講評2000文字以内、キーの完全一致を検査し、`score` や `points` を拒否します。講評は `textContent` で項目の下に表示します。不正なら原文と「結び付けられなかった」旨を表示し、モデルの主張で点数を変えません。変更カードは作らず、結果や資料が変わった後に古い講評を付け直しません。

## 読み取りツール

モデル一覧で `tools` の対応を確認し、利用者が読み取りの許可にチェックした場合だけ `list_files` と `read_file` を提示します。既定は無効で、許可がなければ従来の本文を変えません。前者はパスとバイト数だけ、後者は `validatePath` を通るプロジェクト内の完全一致のパスだけを扱います。引数のキーは完全一致させ、バイナリーと選択できないファイルは拒否します。結果は `PROPOSAL_LIMITS.perFile` までで、超過分を省略した旨を付けます。

逐次受信した `tool_calls` を index ごとに組み立て、完了後に結果の全文をカードに表示します。各要求の採否を選ぶまで返さず、選んだ後も次の本文を確認して「送信する」を押すまで送信しません。未知のツールは拒否します。`READ_TOOL_LIMITS` に従い、応答ごとに4件まで、利用者の相談ごとに3往復までとします。余分な要求は自動で拒否し、往復の上限後はツールを外します。ファイル変更では古いカードと確認を無効にし、現在の結果で確認し直します。ツールの結果も信頼できない資料であり、次の相談では SHA-256 と UTF-8 バイト数に置き換えます。全文の再送は利用者が選ぶ場合だけです。

## 種類を追加する手順

`teach` は7番目の「教師役（ヒント）」です。`allowsChanges: false` とし、構造化出力も使いません。完全な解答や修正後のコード全文を示さず、選んだ段階だけのヒントを出すよう指示します。段階1は見る場所や概念、段階2は具体的な方向、段階3は完全なコードを含めない答えに近い説明です。選択の既定値は1で、段階を相談文に含め、確認した本文をそのまま送信します。資料中の指示に従わない共通方針は変えません。

教師役の場所の引用は、今回本文を送ったファイルの `path:line` に限ります。`ai-references.mjs` で既知のパスと行数を検査し、不明なファイルや範囲外の行は無視します。応答は `textContent` で表示し、有効な位置だけリンクにします。リンクはファイルを開いて行へ移動し、CodeMirror の行装飾で目印を付けます。目印とリンクは消去ボタンか次の送信で消し、資料の内容やプロジェクトが変わった場合も古い位置を残しません。行の引用だけで通信を始めてはいけません。

構造化出力は変更を許す種類または採点の講評で、明示取得したモデル一覧に `structured_outputs` の対応がある場合だけ使います。`response_format` の厳密な JSON Schema と `provider.require_parameters: true` を確認本文に含めます。受信途中は JSON を表示せず、完了後も形式と余分な項目を検査し、変更の `changes` は既存の `validateProposals` に、採点の `comments` は専用の検査に通します。不正な応答は本文だけを表示して適用を拒否し、会話には受信した原文を保持します。非対応時は従来のコードフェンスを使い、自動再送はしません。

構造化した各変更では `path`、`reason`、`content`、`edits` をすべて必須とし、`content` と `edits` は片方だけを null にします。`edits` の各項目は `search` と `replace` の文字列だけです。余分な項目、両方 null、両方指定を拒否します。全文置換も `edits: null` を省略しません。

会話履歴は成功した応答だけを保持します。`ai-history.mjs` で以前の資料を SHA-256 と UTF-8 バイト数に置き換え、既定では本文を再送しません。全文の再送は利用者の選択時だけです。今回の資料は全文を送り、どちらも確認と送信のバイト列を一致させます。ハッシュ計算中の確認を拒否し、会話の消去後に計算結果で履歴を戻してはいけません。

1. `web/lib/ai-skills.mjs` の凍結した `AI_SKILLS` に、一意の `id`、日本語の `label` と `instructions`、`allowsChanges` を追加します。共通の役割、資料の境界、回答方針、出力形式は `buildSystemPrompt` に置き、上限値は定数を参照します。不明な ID の拒否を保ちます。
2. 形式検証の指示を変える前に `web/lib/formal-properties.mjs` を読み、対象セル、モード、クロックの条件と合わせます。プロジェクト要約は `web/lib/ai-project-summary.mjs`、本文の作成と送信は `web/lib/openrouter-chat.mjs`、画面は `web/lib/ai-chat-ui.mjs` を確認します。
3. `tests/web/ai-skills.test.mjs` で項目、資料の境界、変更を許す場合だけの出力形式、定数の上限、不明 ID を確かめます。要約は通常・空の入力、設定の有無、UTF-8 バイト数、本文の除外を検査します。`tests/web/openrouter-chat.test.mjs` で選択外の本文が漏れず、確認と送信のバイト列が一致することを保ちます。
4. `tests/web/ai-proposals.test.mjs` のパス・上限・競合・取り消しと、`tests/web/ai-chat-flow.test.mjs` の状態遷移を通します。`tests/e2e/ai-chat.spec.mjs` で自動送信しないこと、種類変更による確認の取り消し、エラー説明、適用と取り消しを確かめます。新しい状態イベントは安易に増やさず、既存の `inputs_changed` を使います。
5. 画面を変えたら 4 ボードの画面を撮影して目で確かめ、確認範囲を報告します。`docs/research/editor-and-ai.md` の A2 も更新し、日本語の推敲と JIS X 0213 の検査を行います。

```sh
node --test tests/web/ai-*.test.mjs tests/web/openrouter-chat.test.mjs
PLAYWRIGHT_PORT=8123 npx playwright test tests/e2e/ai-chat.spec.mjs
python3 .github/scripts/check-jisx0213.py
git diff --check
```
