## 再監査の結論

| ID | 再確認した事項 | 判定と影響 |

## Analyticsと通信の評価

元ログの外部要求は `https://static.cloudflareinsights.com/beacon.min.js/...` です。6件のconsole記録はwarningで、console error、pageerror、requestfailedの記録はありません。ただし、形式検証の例外はUIで捕捉してログ表示するため、console error 0件はアプリの失敗0件を意味しません。

`web/_headers` のCSPは `connect-src 'self' https://openrouter.ai; base-uri 'self'; form-action 'self'; object-src 'none'; frame-ancestors 'self'` です。`connect-src` はscriptの取得先を制限する `script-src` ではありません。外部script取得、実行可否、beacon送信、HDL送信をそれぞれ区別します。HDLがAnalyticsへ送信されたとする証拠はありません。

Pages側の自動挿入という説明は公開HTMLと整合しますが、管理画面の設定は確認していません。通信説明と一致させるにはAnalytics無効化を推奨します。設定は人間が判断・変更し、その後のHTML、要求、console、隔離ヘッダーを再確認する必要があります。CSPを緩める対応は推奨しません。

## 調査とエージェント運用の改善

| 観点 | 見つかった問題 | 次回の改善 |
|---|---|---|
| プロンプト | 「網羅的」の軸が未定義で、11/12という広い総括になった | ユースケース、ボード、言語、engine、ブラウザー、実機/仮想を事前表にする |
| 知識 | Z3推奨に後続の反例実験が反映されていない | 各推奨に反証検索、最新実験、配布状態の列を付ける |
| 環境 | ローカル404とPagesの200 HTMLが異なる | 配信環境の代替応答を負の対照に含める |
| アクセス | 実機、OpenRouter、Cloudflare管理画面の確認がない | 必要な段階でのみ人間の確認を依頼し、未実行を合格にしない |
| MCP・証拠 | 添付と一時生成物が混在し、元の件数も古い | 最終ファイルを梱包した後に件数とhashを自動集計する |
| 操作手順 | 非表示tab、disabled要素、広すぎるselectorでtimeout | 前提状態をassertし、利用者に見える操作と内部fixture操作を区別 |
