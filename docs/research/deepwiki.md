# DeepWikiの構成と検査

この文書はWikiを保守する開発者向けです。[調査の索引](../../RESEARCH.md#7-分割した調査)から参照できます。設定の正本は [`.devin/wiki.json`](../../.devin/wiki.json) です。Wikiは派生した案内であり、実装、テスト、原記録の代わりではありません。

## 公式仕様と採用した範囲

2026-11-27に[DeepWiki repository wikisの公式説明](https://docs.devin.ai/work-with-devin/deepwiki)を再確認しました。設定には `repo_notes` と、空でない `pages` が必要です。設定がある場合は自動のページ選定を置き換え、列挙したページだけを生成する仕様です。足りない主題が自動で補われることを前提にしません。

[Validation Limits](https://docs.devin.ai/work-with-devin/deepwiki#validation-limits)には次の上限があります。

| 項目 | 公式説明 | 本リポジトリーの検査 |
| --- | --- | --- |
| ページ数 | Maximum 30 pages (80 for enterprise) | 通常枠の1から30ページ。リポジトリーの設定は30ページちょうど |
| ノート総数 | Maximum 100 total notes | repo_notesと全page_notesの合計100件まで。リポジトリーの設定は100件ちょうど |
| ノート本文 | Maximum 10,000 characters per note | 各contentを10,000文字まで |
| タイトル | Page titles must be unique and non-empty | 重複・空白だけのタイトルを拒否 |

`repo_notes` の要素は必須の `content` と任意の `author` を持ちます。ページには必須の `title`・`purpose` と任意の `parent`・`page_notes` を使います。`page_notes` は `content` を持つノート配列として検査します。親の省略と `null` を受け付け、ページの順序には依存しません。

確認した公式ページにはWikiの言語を英語に限定する規定や、言語専用の設定項目はありません。AGENTS.mdに従って本文と見出しを日本語にし、その生成指示もrepo_notesへ明記します。識別子やパスは英語のままです。

公式説明には生成のeffort levelとしてlow、medium、highがあり、mediumとhighはACUを使います。この変更はリポジトリーの設定ファイルを更新するもので、再生成やeffort levelの変更は行いません。

## 30ページ構成へ更新した理由

更新前の設定は20ページ・27ノートでした。一方、2026-11-27時点の公開中のDeepWiki構成には、設定ファイルにない10ページが表示されていました。追加されていた主題は、ブラウザー要件、教師役・採点、端末内補完、外部ソースへのpatch、ビルド高速化、文書の自動検査、Surfer組込み、solver通信、SBY・Python実行基盤、反例再実行の監査です。

この差は、今後の再生成で重要なページが消える危険があることを意味します。そこで公開中の主題を設定ファイルへ取り込み、親子関係を次の6系統に整理しました。

- 午後のFPGAの全体像
- ブラウザー内の構成とデータの流れ
- Web IDEとプロジェクト管理
- 対応ボードと制約
- ビルドとCIの検査
- 開発参加とエージェントの規則

構成の子ページは合成、配置配線、pack、書き込み、シミュレーション、形式検証です。シミュレーションの下にSurfer、形式検証の下にsolver通信、SBY・Python、反例監査を置きます。IDEの子ページはUX契約、OpenRouter、AI相談、教師役、端末内補完、HDLライブラリー、ブラウザー要件です。ビルド・CIの子ページは再現性、Pages公開、仮想USB、patch群、高速化と計測です。開発参加の子ページは調査記録とWikiの保守、文書の自動検査です。

## 100ノートの使い方

上限を単に埋めるのではなく、生成時に参照してほしい資料と混同を防ぐ条件へ使います。配分は `repo_notes` 10件と、30ページそれぞれの `page_notes` 3件です。

repo_notesには、製品の範囲、日本語と資料の優先順位、生成物の扱い、工程境界、書き込みの安全性、公開承認、OpenRouter、形式検証、依存のpin、AI機能の10原則を置きます。全ページに共通する否定条件だけをここへ集めます。

page_notesは各ページで次の3種類に揃えます。

1. 読む実装、テスト、調査、実験のパス
2. 混同してはいけない機能・検証段階・対象外の境界
3. 残すべき否定条件、fail closedの判定、実機や外部サービスとの差

依存の版や性能値を設定へ転記せず、pin checkerや固定条件付きの実験へ戻る構成です。IDCODE、FAILログによる失敗検出、実機未確認、形式検証のunknownや資材未準備、mockと実サービスの差はrepo_notesと該当ページで保持します。

RESEARCH.md、`docs/research/`、`docs/experiments/`、`docs/ux/` を説明の根拠として優先します。ただし初期計画と後続の実装が食い違う場合は、コードとテストで現在の到達範囲を確認し、時点を分けるよう指示します。`vendor/`、`third_party/`、生成した `public_html/`、`docs/ux/out/` は説明の優先度を下げます。これは索引からの強制除外ではなく、外部ソースの接続やライセンスが必要なら参照します。

## 検査と更新

```sh
python3 .github/scripts/check-deepwiki.py
python3 -m unittest discover -s tests/check-deepwiki -v
```

lint workflowで両方を実行します。検査はPython標準ライブラリーだけを使い、公式の通常枠の上限に加え、このリポジトリーの保守方針として次を拒否します。

- 読取り失敗、不正なUTF-8・JSON、重複JSONキー、NaNなどの非標準値
- 必須項目の欠落、型の不一致、未知の項目、空白だけの本文・目的・author
- タイトル前後の空白、存在しない親、自分自身や複数ページを巡る親の循環

文字数はUTF-8のバイト数でなく、Pythonの文字列長で数えます。公式説明には文字数の具体的な数え方の記載がないため、この方式をローカル検査の基準とします。30ページ、合計100ノート、10,000文字の境界と、正常・空・不正入力をテストします。リポジトリーの設定が上限の30ページ・100ノートを使い切っていることもテストで固定します。10件のrepo_notesと各ページ3件のpage_notesの配分、今回取り込んだ10主題の存在も同じテストで確認します。公式に新項目が増えた場合は、未知の項目の検査を外すのではなく、仕様を読み直して検査とテストを更新します。

実際のDeepWiki再生成、公開Wikiへの反映、日本語やページ構成が生成結果に従われることは、この変更では確認していません。JSONと階層の検査は文章の正確さを保証しないため、再生成後はソースリンク、対応範囲、安全上の制約を人間が確認します。
